This report outlines a high-performance, single-core 10Gbps packet forwarding architecture. The goal is to maintain line-rate throughput (~14.88 Mpps for small packets) while implementing a flexible, asynchronous Quality of Service (QoS) layer.
1. Core Architectural Principle: The "Mesh" Pipeline
To achieve 10Gbps on a single core, we move away from traditional "Thread A pushes to Thread B" models, which suffer from high locking overhead and cache misses. Instead, we use a distributed ownership model where every interface thread is both a producer and a potential consumer.
Zero-Copy Handover: We never move packet data. We move 64-bit memory pointers (descriptors) that stay in the CPU’s L1/L2 cache throughout the entire process.
Run-to-Completion (RTC) Hybrid: Each thread follows a "harvest-process-flush" loop. If a thread is idle, it "steals" work from busy interfaces to keep the CPU saturated.
2. The "Swap-Queue" Mechanism
To decouple the Ingress (receiving) from the Egress (QoS/sending) without using slow mutexes, we use Double-Buffered Shadow Queues.
Each interface has an Active Ingress Queue and a Swap Queue.
The Interface Thread fills the Active Queue.
Once a Batch Threshold (e.g., 32 packets) is met, the thread performs an Atomic Swap of the pointers.
The Interface now has a fresh, empty queue to continue receiving, while the full batch is "locked in" and ready for the QoS layer.
3. The "Global Ready Mask" (The Central Nervous System)
Instead of a centralized software queue (which requires multiple instructions to manage), we use a Global Bitmask (uint64_t) to signal work availability.
The "Ready" Signal: When an interface thread completes a swap (a full batch is ready), it sets its corresponding bit in the global_mask using an atomic OR operation.
Work Stealing: Any thread that finishes its own tasks checks this bitmask. If a bit is set, that thread "claims" the batch and handles the egress for that interface.
4. Ultra-Low Cycle Optimization (The Implementation)
To stay under the ~268 CPU cycle budget per packet, the logic is condensed into raw hardware instructions:
Finding Work (TZCNT): We use __builtin_ctzll to find the first set bit in the mask instantly (3 cycles). This avoids looping through interfaces.
Claiming Work (LOCK BTR): We use a single x86 Bit Test and Reset instruction. It checks if a bit is 1 and flips it to 0 in one unbreakable hardware step. This prevents two threads from ever emptying the same batch.
The "Half-Batch" Rule: Threads only check the global mask when they are idle or have processed at least half of their own batch. This prevents "Cache Line Bouncing" (where cores fight over the same memory address).
5. Summary of the Forwarding Loop
Each interface thread runs this high-speed cycle:
Ingress: Poll NIC HW 
 Classify 
 Stuff into target's Swap Queue.
Signal: If Target Queue == 32, perform Atomic Swap and Set Bit in Global Mask.
Check: Does global_mask != 0?
Steal: If yes, use LOCK BTR to claim a batch.
Egress: Run QoS logic on the claimed batch

6. Performance Expectations
Feature	Impact
Batching (32)	Spreads the "PCIe Doorbell" and "Sync" cost across 32 packets.
Bitmask Logic	Reduces "Find Work" overhead from $\sim$500 cycles to $\sim$25 cycles.
Cache Locality	Keeps packet headers in L2 cache by avoiding cross-core data moves.
This architecture ensures that "Quiet" interfaces help "Busy" ones, latency is kept to microsecond levels via time-based flushes, and the CPU spends 95% of its time moving data rather than managing locks.
